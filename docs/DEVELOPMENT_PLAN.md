# 우주공강 개발 계획

## 1. 제품 목표

사용자가 웹 브라우저에서 시간표를 등록하면 공강 시간을 확인하고, 같은 시간에 가능한 활동을 모집하거나 참여한 뒤 단체 채팅으로 약속을 조율할 수 있게 한다.

핵심 사용자 흐름은 다음과 같다.

`로그인 → 시간표 등록 → 공강 확인 → 모집글 조회/작성 → 참여 → 단체 채팅`

## 2. MVP 범위

### 포함

- 이메일 기반 회원가입과 로그인
- 닉네임, 학과 등의 프로필 관리
- 요일, 시작 시간, 종료 시간 기반 수업 등록/수정/삭제
- 등록된 수업 사이의 공강 시간 표시
- 식사, 운동, 공부, 카페, 기타 카테고리
- 공강 시간과 모집 인원을 포함한 모집글 작성
- 모집글 목록, 상세 화면, 참여와 참여 취소
- 모집 마감 처리
- 모집글별 단체 채팅

### 제외

- 팀 프로젝트 팀원 모집
- 빈 강의실 조회와 대여
- 택시 동승 전용 기능
- 결제, 광고, 학교 인증
- 모바일 전용 네이티브 앱

## 3. 화면 구성

| 영역 | 화면 | 핵심 기능 |
|---|---|---|
| 인증 | 로그인, 회원가입 | 계정 생성 및 인증 |
| 홈 | 오늘의 공강, 추천 모집 | 핵심 정보 요약 |
| 시간표 | 주간 시간표, 수업 편집 | 수업 등록과 공강 계산 |
| 모집 | 목록, 작성, 상세 | 검색, 작성, 참여, 마감 |
| 채팅 | 채팅방 목록, 대화 | 모집글별 메시지 전송 |
| 내 정보 | 프로필, 내 모집/참여 | 사용자 정보 관리 |

모바일 화면은 하단 메뉴, PC 화면은 상단 메뉴로 `홈 / 시간표 / 모집 / 채팅 / 내 정보`를 제공한다.

## 4. 기술 구조

```text
Web Browser (HTML/CSS/JavaScript)
  ├─ REST API ─────── Spring Boot ───── MySQL
  └─ WebSocket ────── Chat Handler ──── MySQL
```

- HTML/CSS/JavaScript는 반응형 화면 표시와 사용자 입력을 담당한다.
- 정적 웹 파일은 Spring Boot가 함께 제공한다.
- Spring Boot는 인증, 권한, 공강 계산, 모집 인원 검증을 담당한다.
- MySQL을 단일 데이터 저장소로 사용해 프로젝트 복잡도를 낮춘다.
- 채팅은 WebSocket으로 실시간 전송하고 메시지는 MySQL에 보관한다.

## 5. 핵심 데이터 모델

| 테이블 | 주요 필드 |
|---|---|
| users | id, email, password_hash, nickname, department |
| courses | id, user_id, title, day_of_week, start_time, end_time |
| posts | id, author_id, category, title, content, activity_at, capacity, status |
| participants | id, post_id, user_id, joined_at |
| chat_rooms | id, post_id, created_at |
| chat_messages | id, room_id, sender_id, content, sent_at |

중요 제약조건:

- 같은 사용자의 수업 시간이 겹치면 등록할 수 없다.
- 작성자는 모집 참여자에 자동 포함한다.
- 동일 모집글에 중복 참여할 수 없다.
- 정원이 차면 추가 참여할 수 없다.
- 모집글 작성자만 모집을 마감할 수 있다.

## 6. 개발 일정

### 0단계: 준비

- Git 저장소와 브랜치 규칙 설정
- IntelliJ IDEA 또는 Eclipse, JDK 17, MySQL 설치
- 웹 화면과 서버 기본 프로젝트 실행 확인

### 1차 스프린트: 회원과 프로필

- 사용자 테이블 및 회원 API
- 반응형 회원가입, 로그인 화면
- 비밀번호 암호화와 인증 토큰
- 프로필 조회 및 수정

완료 조건: 회원가입 후 로그인해 내 프로필을 조회할 수 있다.

### 2차 스프린트: 시간표와 공강

- 수업 CRUD API
- 주간 시간표 화면
- 수업 시간 중복 검사
- 공강 시간 계산

완료 조건: 수업을 등록하면 주간 시간표와 공강 시간이 표시된다.

### 3차 스프린트: 모집과 참여

- 모집글 CRUD API와 목록 필터
- 모집글 작성, 목록, 상세 화면
- 참여, 취소, 정원, 마감 처리

완료 조건: 공강 시간에 모집글을 만들고 다른 계정으로 참여할 수 있다.

### 4차 스프린트: 채팅

- 모집글별 채팅방 생성
- WebSocket 연결 및 메시지 저장
- 채팅방 목록과 대화 화면

완료 조건: 같은 모집글 참여자끼리 실시간 메시지를 주고받을 수 있다.

### 5차 스프린트: 통합 및 발표 준비

- 예외 처리와 입력 검증
- 주요 사용자 흐름 테스트
- UI 정리와 시연 데이터 준비
- 발표 자료와 시연 영상 제작

## 7. 협업 규칙

- `main`: 발표 가능한 안정 버전
- `develop`: 기능을 합치는 통합 브랜치
- `feature/기능명`: 개인 기능 개발 브랜치
- 커밋은 한 가지 변경만 담는다.
- API가 바뀌면 `docs/API_SPEC.md`도 함께 수정한다.
- 병합 전에 작성자 외 팀원 한 명이 코드를 확인한다.

## 8. 바로 할 일

1. 모든 팀원이 기술 구성과 MVP 범위에 동의한다.
2. 담당자를 프론트엔드, 서버, DB/테스트 영역으로 나눈다.
3. 개발 환경을 설치하고 기본 프로젝트 실행 화면을 공유한다.
4. 회원가입 API와 웹 로그인 화면부터 구현한다.
